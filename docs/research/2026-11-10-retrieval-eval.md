## 1. okl's mechanics against the research

| Mechanic | Verdict | Why |
|---|---|---|
| BM25 over title, symptom, fix, body, tags, aliases, triggers | Supported as a first stage only | Lexical match is weak when targets share few words with the query: nDCG@10 14.3 [R1], 22.32 on tool retrieval [R6], 29.6% file recall on SWE-bench [R8]. Yet removing BM25 from an LLM localizer cost 11 points [R11], and on commit messages BM25 beat dense, 79.7 vs 73.6 [R12]. Triggers are document expansion, which lifted BM25 RR@10 from 0.185 to 0.277 [R18]. |
| Static embedding fused linearly | Supported in form | Linear fusion beat reciprocal-rank fusion in and out of domain, its one weight settling on a few labelled queries [R16]; hybrid beat either scorer almost everywhere [R19]. Disagreement: dense led on library docs (33.1 vs 5.2) [R25], BM25 on commit messages [R12]. No paper tests static embeddings. |
| Cross-encoder reranker off | Supported | Off-domain cross-encoders lowered BM25's 14.3 to 8.3 at k=100 [R1] and an embedder's 33.83 to 28.92 [R6], and were robust in only 22–23% of experiments [R24]. LLM listwise reranking helped [R1, R3, R10, R24], though a gpt-3.5 one lost to its embedder [R6]. |
| Calibrated 5 plus a 12-slot overlap floor | Departs | Oracle per-query cut-offs beat every fixed depth [R20]; a largest-score-gap cut matched or beat fixed k with up to 10× fewer tokens [R21]; a global threshold failed in production and was replaced by per-rule ones [R14]. Widening is no fix: more context lowered SWE-bench resolution [R8], and high-scoring near misses, which an overlap floor admits, hurt the reader [R5, R22, R23]. Disagreement: learned cut-off predictors did not beat a good fixed depth [R20]. |
| Closed tags; `applies_to` | No evidence | Only weak support: filtering irrelevant folders helped localization [R9]. okl's §4d is the only measurement. |
| Retrieval by governed paths | Supported | Structural links reach what words cannot: +5.5 points from graph traversal [R11], +4.9 from commit memory [R12]; production needed scoping to changed lines [R14]. Auto-inferred doc-to-code links are unreliable (F1 about 0.2) [S10]. |
| Task words find 14–21% | Expected | The same range as [R1, R6, R8]. |
| Code, or a model's explanation of it, as the query: no better | Departs, likely cause known | Generated queries helped BM25 most: +12.2 nDCG@10 when a model reasons about what the relevant document should contain [R1], +3–15% with pseudo-documents [R26, R27], MRR 12.6 → 35.1 with generated code [R13]; expansion helps weak retrievers [R17]. Each positive case imitates the target document; okl's explanation described the input. |
| A model reads every one-liner and picks ten: 40–52% | Supported, with a scale limit | LLM listwise ranking beat BM25 (53.68 vs 43.42) [R3]; an LLM reading a file tree beat embeddings, 78.67% vs 70.33%, union 81.67% [R9]; a corpus in a 128k context matched a trained retriever [R2]. But order (65.80 in score order, 25.17 random) [R3] and position [R5] matter; with no shared words 11 of 13 models fell below half their short-context score by 32K tokens [R4]; catalog growth cost 7–85% [R7]. LOFT and NoLiMa reconcile: LOFT's tasks keep literal overlap. |
| A needed lesson pushed from 17th to 18th | Expected | A fixed k under a growing store; see the caps row. |
| Proof: a stored check, stamped only on a pass | Supported; one detection source | Test-based detection of doc–code inconsistency: precision .88 balanced and .39 at 10% prevalence, against .10–.20 for single-prompt LLMs, at recall .21 [S6]. SWE-bench's fail-to-pass rule is the same idea [R8]. |
| Drift: governed files changed, STALE, gate | Supported as a trigger; precision weak | Detectors given the diff beat those without (F1 about 77 vs 66), and "text names a token the diff deleted" beat every diff-less model [S3, 2021]. Stale doc references reach 28.9% of top projects, and the published detector runs per PR [S1, S2]. But co-change labels were 26–46% wrong [S5, S7], change-triggered advice reached 0.28 precision at real prevalence [S8], and half the answered reports were false positives [S1], consistent with okl's 0.22%. Links bound detection [S9]. |
| `okl review`: 8 of 10 planted details | Recall only | LLMs flag 90–98% of functions [S7]; GPT-4 given a diff: precision 51.5, recall 98.8 [S4]; precision falls with prevalence, and "Is there an inconsistency?" is stricter than "Are they consistent?" [S6]. |
| Drift: 14 of 36, 16 of 24 planted breaks | Caution | Synthetic breaks overstate detectors: precision 0.83 → 0.08 on natural pairs [S7]; the same caveat applies to [S9]. |
| Pre-registration, receipts, judge ≠ generator | Supported | Unnoticed deviation is pre-registration's main gap [E20], which committed receipts close; registered reports are established in SE [E21]; see REFORMS [E22]. Self-recognition drives self-preference [E3, E1]. Same-family judges are untested. |
| Opus-judged answer keys, audit pending | Departs: not gold yet | Per-item LLM labels agree only fairly (κ 0.31–0.50) while system rankings agree (τ 0.87–0.94) [E8]; at the top τ fell to 0.51, a run moved from 5th to 28th under human grading, and a model grading model rankers is circular [E9]; paraphrases moved κ across 0.50–0.71 [E7]; reliability is task-specific [E4, E6]. A judge no better than the system at most halves the human labels needed [E11]; prediction-powered inference uses a model key over a random human sample [E10]. |
| Three models agree about half the time | A warning sign | Model–model agreement predicts human–model agreement (Spearman 0.65); on "does this change fix this static-analysis warning", Krippendorff's α was 0.80 among humans, 0.15 human–model, 0.12 model–model [E5]. Two binary judges agreeing on half the items means one is wrong on at least a quarter. |
| A/B on 8 seeded tasks, 42% → 7% | Direction supported, intervals understated | Below a few hundred items, use Wilson or Bayesian intervals [E19]; cluster and pair [E18]. Wilson, my arithmetic: 41.7% [34.4, 49.4] against 6.7% [3.8, 11.6] if attempts were independent; with 8 tasks the effective sample is nearer 8. |
| Planned outcome replay graded by the fix's test | Supported, with known failure modes | Fail-to-pass tests [R8]; but weak tests credited 31% of passes [E13], 29.6% of plausible patches behave differently from the real fix [E14], test repairs changed 24–41% of leaderboard entries [E15]; memorisation inflates public-repository tasks [E16, E17]; a lesson recorded from the replayed fix is temporal leakage [E23]. |

## 2. Changes, ranked by expected benefit against cost

1. **Fix the answer key first** (cheap; every retrieval figure rests on it): hand-audit a random sample sized for prediction-powered inference; report α among humans, human–model and model–model; send model disagreements and order-flips to humans first; keep the judge outside the picker's model family, and audit the model-picks arm's hits and misses [E5, E10, E11, E9, E2].
2. **Make the model reader a second stage** over a wider list in score order, unioned with the top lexical and governed-path hits; cap the list and re-measure as the store grows [R3, R9, R10, R2; limits R4, R5, R7].
3. **Replace the 5 + 12 caps** with a largest-score-gap cut or per-lesson thresholds; never widen k to rescue a miss [R21, R14, R20, R8, R22].
4. **Re-run the query test with a hypothetical-lesson prompt** ("write the lesson this change could break") into BM25: one prompt, testing the likely cause of the null [R1, R26, R27, R17, R13].
5. **Add a deleted-identifier trigger to drift**; keep governed paths declared by people, with suggestions only [S3, S1, S10, S9].
6. **Measure `okl review`'s false positives** on unbroken lessons at the observed stale rate; add naturally stale lessons mined from history; use the stricter wording [S6, S7, S8].
7. **Re-report the A/B per task, paired**, with Wilson or Bayesian intervals [E18, E19].
8. **Guard the replay**: rewind the store to the base commit; confirm fail-before, pass-after; drop tests that call fix-introduced names; check credited passes against the real fix; prefer bugs fixed after the model's cutoff; keep a paired no-briefing arm [R8, E13–E17, E23].
9. **Tune the fusion weight on the audited key**; try an identifier-aware tokenizer; drop generated triggers that score poorly against their own lesson [R16, R12, R18].
10. **Leave per-field weights alone** until labels exist: undertuned field weights did worse than one field [R19].

## 3. What the research leaves open

- No paper measures retrieving team rules or lessons for a diff against a labelled set; the nearest learns rule selection from about 800k review comments [R14].
- None measures judge reliability on "does this diff break this lesson"; on the nearest SE task, models failed [E5].
- None compares a file-change trigger with a model reading the text on the same breaks, or measures staleness of rule files or of lessons that carry checks; execution-based detection rests on one paper [S6]. Rule files accrete and rarely shrink [S11, S12]; adding every memory hurt agents [S13]; memory systems fail to forget superseded facts [S14].
- The model reader's limit for non-literal relevance at okl's size (a few hundred one-liners) lies between LOFT's parity and NoLiMa's collapse; no study here measured it.
- No small-data cut-off predictor is validated [R20].
- Hard metadata filters and static embeddings: no evidence found.
- Always-on context files did not significantly change agent success (model-written −0.5% and −2%, at 20–23% more cost; developer-written +2.4%) [R15]; no study compares them with per-task selected lessons.
