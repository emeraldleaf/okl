Guardrails and a learning loop for AI coding agents
Joshua Dellemeraldleaf.dev · open source, MIT

Hold your agent to your rules,
and let each session teach the next

okl works with your agent: it brings your rules and ADRs into context before each task, proves them with checks you choose, and blocks the push when the code they govern changes.

Decided up front

Your rules and ADRs · this codebase · vetted outside advice
once

The store

Rules · decisions · past defects · gates
one local file

In front of the agent

Task arrives → ranked and filtered → briefing in context
before every task *

Gated as code moves

A check must pass → its files change → push or CI fails until it passes again
on every push

Kept current

Update keeps proof · retire with a reason · end-of-session recap
at session end *

* Claude Code hooks brief every prompt and ask at session end; other MCP agents call okl_check. The push gate works with any agent.
